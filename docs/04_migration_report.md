## 4. Taxonomy Conflict Resolution & Coexistence

### The Problem:
- **Legacy publication taxonomy**: Publications in `slscm_publications_2025_2026.json` were categorized under:
  - `operational_optimization` (8 papers)
  - `ml_optimization` (4 papers)
  - `green_transportation` (6 papers)
- **New Lab Research Pillars**: Defined in `slscm_overview.json`:
  - `supply_chain_optimization`
  - `ai_supply_chain_intelligence`
  - `decision_analytics`

### Resolution:
1. In `publications` table, both columns are stored:
   - `research_pillar`: Retains the legacy taxonomy value to maintain 100% filter compatibility on `PublicationsPage.tsx`.
   - `primary_pillar_id`: Maps to the new strategic pillar IDs (`supply_chain_optimization`, `ai_supply_chain_intelligence`, `decision_analytics`).
2. In TypeScript types (`web/src/types/index.ts`):
   ```ts
   export type LegacyPublicationPillarId =
     | 'operational_optimization'
     | 'ml_optimization'
     | 'green_transportation';

   export type ResearchPillarId =
     | 'supply_chain_optimization'
     | 'ai_supply_chain_intelligence'
     | 'decision_analytics';

   export type PillarId = ResearchPillarId;
   ```
3. `publicationRepository.ts`:
   - `getPublicationsByPillar(pillarId)` checks both `research_pillar` and `primary_pillar_id`, ensuring queries from either taxonomy resolve seamlessly without type coercion or visual regression.

## 5. Assumptions & Modeling Decisions

1. **Static Pre-Rendering**: Since the lab platform targets GitHub Pages (`slscm-lab.github.io`) and Vercel edge delivery, generated JSON build artifacts (`web/src/data/generated/*.json`) are committed as build assets.
2. **Authors Normalization**: The `publication_authors` table preserves both the author's order and the `is_highlighted` boolean (indicating internal lab members).
3. **Derived Metrics**: All hero counter metrics (`total_publications`, `q1_journals`, `active_projects`, `phd_msc_scholarships`) are computed directly from SQL queries during `export_data.py`.
